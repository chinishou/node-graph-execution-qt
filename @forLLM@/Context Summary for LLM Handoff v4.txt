1. Architecture Question & Design Rationale
Q: Why should node connections be stored in NetworkModel instead of NodeModel?

A: Graph-level management benefits:

Global validation: Cycle detection requires full graph visibility
Topological sorting: Execution order needs complete dependency graph
Separation of concerns:
Node: Knows "what connectors I have"
Connector: Knows "who I'm connected to"
Network: Knows "entire graph structure" and validates
Transactional operations: Network ensures atomic connect/disconnect
Serialization: Easy to export complete connection list

def _get_unique_node_name(self, base_name: str) -> str:
    """Generate unique node name by adding suffix if needed (_1, _2, etc.)"""
    existing_names = {node.name for node in self._nodes.values()}
    if base_name not in existing_names:
        return base_name
    
    # Strip existing suffix and find next available
    match = re.match(r'^(.+?)_(\d+)$', base_name)
    if match:
        base_name = match.group(1)
    
    counter = 1
    while f"{base_name}_{counter}" in existing_names:
        counter += 1
    return f"{base_name}_{counter}"

2.3 Connection Storage Optimization
Changed: From dynamic computation to direct storage

Before:

def connections(self) -> List[Tuple[ConnectorModel, ConnectorModel]]:
    conns = []
    for node in self._nodes.values():
        for output in node.outputs().values():
            for connected_input in output.connections():
                if connected_input.is_input():
                    conns.append((output, connected_input))
    return conns
After:

# Storage
_connector_pairs: List[Tuple[ConnectorModel, ConnectorModel]] = []

# Access
def connector_pairs(self) -> List[Tuple[ConnectorModel, ConnectorModel]]:
    return self._connector_pairs.copy()

# Management
def connect(...):
    if success:
        self._connector_pairs.append((source_connector, target_connector))

def disconnect(...):
    if success:
        self._connector_pairs = [
            (src, tgt) for src, tgt in self._connector_pairs
            if not (src is source_connector and tgt is target_connector)
        ]
Benefits:

O(1) access instead of O(n²) iteration
Clear distinction: ConnectorModel.connections() vs NetworkModel.connector_pairs()
Direct manipulation in connect/disconnect

Key Design Decisions
1. Why Store Connections in Network?
Cycle Detection: Needs full graph visibility
Topological Sort: Requires complete dependency graph
Validation: Cross-node validation at connection time
Serialization: Centralized connection export
2. Why UUID for Node IDs?
Type Safety: Prevents string ID accidents
Uniqueness: Guaranteed globally unique
Future Subnets: Can have same-named nodes in different scopes
3. Why connector_pairs() instead of connections()?
Avoid Confusion: ConnectorModel.connections() exists
Clarity: Network stores pairs of connectors, not individual connections
Performance: Direct storage vs dynamic computation
