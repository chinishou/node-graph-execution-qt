3. Cycle Detection at Connection Time
User Requirement:

"connect時立即檢測cycle，return False + warning，不用整個報錯"
Translation: Detect cycles immediately at connect time, return False with warning instead of throwing errors
Implementation:

def connect(...) -> bool:
    success = source_connector.connect_to(target_connector)
    if success:
        if self.has_cycle():
            source_connector.disconnect_from(target_connector)
            print(f"Warning: Connection from {source_node.name}.{source_output} to {target_node.name}.{target_input} would create a cycle")
            return False
    return success
Benefit: Prevents invalid graph states from being created

4. Performance Optimization
User Question: "get_execution_order可以用defaultdict跟deque優化嗎?"

Optimization Applied:

Replaced list.pop(0) (O(n)) with deque.popleft() (O(1))
Used defaultdict(int) and defaultdict(list) for cleaner initialization
Significant performance improvement for 100-node networks (user's expected scale)
Code Change:

# Before:
queue = [node.id for node in nodes if in_degree[node.id] == 0]
while queue:
    node_id = queue.pop(0)  # O(n) operation

# After:
queue = deque([node.id for node in nodes if in_degree[node.id] == 0])
while queue:
    node_id = queue.popleft()  # O(1) operation

Execution Flow
User calls: target_node.execute()
    ↓
1. Get all ancestor node IDs (_get_all_ancestors)
    ↓
2. Get full network execution order (get_execution_order)
    ↓
3. Filter to ancestors + self
    ↓
4. Cook each node in topological order
    - If caching enabled: only cook dirty nodes
    - If caching disabled: cook all nodes
Dirty State Propagation
Downstream propagation: When node becomes dirty → all child nodes marked dirty
Upstream dependencies: execute() checks dirty state before cooking
Caching behavior:
enable_caching=True: Nodes track dirty state, skip clean nodes
enable_caching=False: All nodes always dirty, always recompute

Cycle Detection: Proactive (at connect time) rather than reactive (at execution time)
Error Handling: Return False with warning instead of raising exceptions for cycles

Terminology: parent/child preferred over upstream/downstream
